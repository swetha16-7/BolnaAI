# BolnaAI Application Functionality Audit

**Audit date:** 2026-10-14  
**Scope:** Source and tests in this repository; no feature implementation performed.

## Executive summary

The application has a working foundation for authenticated organization-scoped
agent and contact CRUD, dashboard aggregates, call history, consent checks, and
Retell/Twilio call-event handling. Several important product areas are only
screens or local state, and the analytics page contains fixed sample metrics.
There is no end-to-end evidence that the application is connected to a live
database or provider in the current deployment.

**Recommended first task: implement secure organization-scoped team membership
management and invitations.** Registration currently creates a new workspace
and its owner; there is no way in the UI or API to add another person to that
workspace. This blocks collaboration and leaves the modeled membership roles
without a usable administration path. An invitation flow should be designed
around expiring, single-use tokens and an explicitly configured delivery
mechanism, with role checks, tenant-scoped queries, audit events, and route-level
authorization tests.

## Audit method and limits

- Traced the app shell and feature views to their client state, API routes,
  server helpers, Prisma models/migrations, and existing tests.
- Checked the checked-in environment template and README. The template uses
  placeholder provider values and has outbound-call gates set to `false`.
- Did not open, record, or change `.env`; Prisma validation loads environment
  variables internally but did not print their values. No provider request or
  real call was made. No database connection, migration, or data mutation was
  performed.
- A passing typecheck, helper/unit tests, and schema validation do not prove
  production deployment readiness, live credentials, webhook reachability, or
  route-level tenant isolation.

## Recommended first implementation task

Implement **secure organization-scoped team membership management and
invitations**, starting with the membership API and authorization tests before
wiring the existing Team page. This is the clearest foundational gap: the data
model already supports memberships and roles, but registered users cannot
invite coworkers or manage who belongs to their workspace. Solving that makes
the organization boundary operational rather than only implicit in server
queries. Keep the workflow independent of live calling, and do not enable
outbound calls as part of this work.
